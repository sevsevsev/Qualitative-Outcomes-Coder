# CP-12-25: Stale "(located)" tags, set from the registry by script, and five empty registry fields

**In plain words.** Each code carries a short note on its evidence (the `basis` field) that marks
each source "verified" (a checker read it and quoted it) or "located" (found but not yet read).
Twenty of those marks still say "located" although the source record has since been read, so the
notes understate the evidence; the same stale word sits in a few source records. This change adds a
small script that sets each mark from the source record itself, so the two can no longer drift
apart, and a test that fails if they do. It also fills in the missing level and publisher on five
health source records. The coding model never reads these notes, so this lands now; the marks on
the academic codes and on Participation in Enriching Activities (Y2.6) wait until the two open pull
requests that edit those codes have merged.

## Change

### Script: `codebook-refinement/v3/refresh_basis_status.py`

Reads `codebooks/youthOutcomesV3.data.ts` and `codebook-refinement/sources/youth_outcomes_v3.sources.json`.
For each row of a fixed table `TAGS = [(code, phrase, source_id), ...]` (the 20 rows above; the
phrase is the source name as it appears right before the tag), it:

1. asserts the phrase occurs exactly once in that code's `basis`;
2. if the next tag is "(located" and the registry `status` of `source_id` is `verified`, replaces
   only the word "located" with "verified", keeping any text after it inside the parentheses
   (row 12 becomes "(verified; CP-01-07's use checked as partial)");
3. leaves the tag as it is if the source is still `located`;
4. skips codes in `WAIT = {'Y1.1','Y1.7','Y1.8','Y1.13','Y1.15','Y2.6','F1.9','F2.3','A2.6'}`
   (emptied, one entry at a time, by the CP that clears each wait), and skips a row whose tag
   already reads "verified";
5. prints every changed line for review and writes the file only with `--write`.

It touches nothing else in the file. Run: `python3 codebook-refinement/v3/refresh_basis_status.py --write`.

**Y8.10 `basis`, before:**

```
Search Institute 40 Developmental Assets, Safety (located; CP-01-07's use checked as partial).
```

**After (the script's output):**

```
Search Institute 40 Developmental Assets, Safety (verified; CP-01-07's use checked as partial).
```

### Test: `codebooks/youthOutcomesV3.test.ts`, new `it` in "codebook 3.x source registry"

```ts
it('tags a basis source "located" only if the registry still has a located source for that code', () => {
  // WAIT mirrors refresh_basis_status.py; remove a code once its PR has merged and the script has run.
  const WAIT = new Set(['Y1.1','Y1.7','Y1.8','Y1.13','Y1.15','Y2.6','F1.9','F2.3','A2.6']);
  const located = new Set(reg.sources.filter(s => s.status === 'located').flatMap(s => s.supports.map(x => x.code)));
  const stale = allCodes.filter(c => /\(located\b/.test(c.basis ?? '') && !located.has(c.id)).map(c => c.id);
  expect(stale.filter(id => !WAIT.has(id)), 'stale "(located" tags: run refresh_basis_status.py').toEqual([]);
  expect([...WAIT].filter(id => !stale.includes(id)), 'fixed: remove from WAIT').toEqual([]);
});
```

(`reg` and `allCodes` are the registry and code list the file already loads; use their local
names.) The second expectation makes the wait list shrink as each PR merges, like
`PAIRS_WITHOUT_CF` in `sync.test.ts`. Because per-domain CPs may land in any order, the test is
added in the same commit as the script run, and its `WAIT` set is the set of codes still stale at
that moment.
