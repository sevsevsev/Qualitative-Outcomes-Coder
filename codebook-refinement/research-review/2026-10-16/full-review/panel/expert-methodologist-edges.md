## Missed issues

1. **Blind coders are not the production coder.** All three blind coders are Claude models; production coding is Gemini. Unanimous blind agreement (hint 1, puberty, eating) shows the rule is clear to a careful reader. It does not show Gemini follows it. Every hint's gate must run on Gemini, and agreement among the blind coders shows that the code is stable, not that it is correct.
2. **Invented rows inflate agreement and are circular.** 43 of 75 rows were written by the same pipeline that drafted the rules, as clean exemplars. Real statements carry the hard cases: 9 of the 11 rows where the coders split are real (43 % of all rows are real), and so are 13 of the 18 rows where the coders split or departed from the intended side. In gold, record each row's origin and report accuracy on real and invented rows separately. Prefer real queue rows as evidence for CFs and FDs (for example, FD-P51 should not rest on P-24).
3. **Compound rows used as one-side evidence.** P-19, P-23 and P-73 each carry two results. They should not serve as the "two rows per side" for a CF or an FD, because a split row cannot show which side the rule chose.
4. **Domain-only is becoming a catch-all.** G9 gap routes now exist or are proposed in Y1, Y4, Y8, F1, F2, A1, A2 and A3. Keep a gap register with a set threshold (for example, N unique texts across at least k programs triggers a code proposal), and track the domain-only rate per domain in each eval. Report agreement on code versus domain-only separately, since that line is likely the least reliable one in the codebook.
5. **Rules that key on measure form or verbs.** Several proposals turn on how the outcome is measured (a count versus one person for A1.3, "reduce or prevent" for Y4.12/Y8) rather than on the construct. Coders apply construct tests more reliably. Each such trigger should be restated as "what changes, and for whom", with the measure form named only as a non-trigger.
